# 技术边界与验证声明

适用于 `0.2.0-rc.1` 公开候选。程序保证以通过随包脚本执行、协作式本地进程且没有同权限恶意写入为前提；这不是宿主 Agent 的权限隔离承诺。历史包、真实 Agent 演示与本次新包验收分别记录在 [验证记录](../docs/validation.md)，不能互相替代。

## 程序可保证（协作式本地进程，无恶意同权限写入）

- init 拒绝非空目录；inspect 无写入；adopt 要求六个一级分类、无符号链接、无既有状态和 exact 根路径确认，不改旧正文。
- 每次 ingest 明确一个路径和非空范围，配置渠道匹配，hash 存原字节；重复同 hash 不再创建来源，重放先验证档案。
- 候选精确字段/类型、来源 quote 校验、正式路径范围、无隐藏/保留路径、拒绝符号链接、create 不覆盖、replace 两次旧 hash 检查。
- exact ID 部分 approve/reject/later，敏感/结构/整页替换的每项独立 boolean 门槛；未涉及项保持待审。拒绝 exact source+claim_key 或 exact source+quote 不复活。
- 更新正式页日期、来源 IDs 和资料日期；事务备份及动作日志；独占写锁、持久化 journal 前滚、先预检所有 old/new hash 再恢复；审批四个文件边界真实故障注入测试。
- context 只返回前五类正式 Markdown及来源元数据，不返回 pending、原文或备份；来源字节完整性验证；check 同样排除收件箱/备份。

## Agent 必须落实（程序不能证明）

用户授权是否真实、scope 文本是否精确、当前远端 Agent 是否能读资料、语义提取是否正确、quote 是否足够、是否自述/他述/已采纳、敏感标记是否完整、事实/判断/计划是否正确、旧知识是否完整保留、语义重复及不同 quote 的拒绝是否绕过、新路径是否符合用户认知。程序门槛是确定性核对，不是授权证据鉴定。

新会话从 context 读正式页，在授权范围内按 evidence 核查；不可把待审当真。已有库中无来源元数据的旧页会报告问题；接管不自动伪造来源，也不阻止只读检索这些原有用户知识。Agent 应说明来源不足。

## 明确非保证

- 不是沙箱、访问控制、加密或防止 Agent 直接写文件的系统；metadata 的 sensitive 只标记，不限制 OS 权限。备份和 journal 明文，与原库同磁盘，不替代外部备份。
- path 检查不防同权限恶意进程并发替换路径（TOCTOU），不保证硬链接隔离；不要用不可信的共享可写目录。无大文件/特殊文件/拒绝服务资源隔离。
- journal 保证已持久化 journal 下的协作式进程崩溃前滚，不是多个文件瞬间原子交换。直接读取磁盘的人可能看到中间状态；context/check 在观察到锁时停止，但不提供严格并发快照隔离。不要并发编辑。
- 文件 fsync + os.replace；未做父目录 fsync，不对掉电、文件系统损坏、网络盘或系统级重启持久性作保证。磁盘写满、断权限等错误可能留下锁/备份，需要人工诊断，不自动删除锁。
- 初始化/接管本身不纳入多文件 journal，若创建过程异常可能留下部分空结构；保留现场，不重跑覆盖。
- check 是简单 Markdown链接/来源检查，不验证网页 URL、锚点、完整Markdown语法、所有历史状态或语义真伪；不扫描原始资料发现“知识错误”。
- 本版不做自动索引页维护、重命名迁移、跨文档语义冲突解决、独立多个来源在同一 candidate 的复合证据、状态格式迁移、语义向量检索、大库分页、自动备份清理、实时聊天连接器或调度。
- formal 替换模式需要 Agent 提交完整正文；程序没有三方语义合并器。旧 hash 防止覆写并发编辑，但无法判断 Agent 是否删了有用内容。

## 兼容与可复验

核心设计要求 Python 3.10+，只使用标准库，不导入 Hermes；最低 3.10 runtime 尚未实际验证。根 SKILL 的 platforms 表示设计目标，不代表所有系统通过测试。doctor 中 current/file 的 verified 指提供的本地文件接口，不证明宿主工具、消息平台或端到端操作兼容。

已有真实 Codex 0.163.0 宿主界面、隔离 Debian 虚拟机文件／命令和远端模型组合下的安装解压、建库、候选提取、部分批准及新会话只读演示。该记录不证明全局注册、原生发现、Claude Code 新包兼容、原生 Windows 或 macOS 兼容。核心不要求账号，但语义处理使用的 Agent 模型可能需要账号、产生费用并向模型提供方发送资料；须单独取得处理许可。

历史 0.1.0 ZIP 的已测环境、包哈希和结果，以及 0.2.0-rc.1 本次新包的待运行项目，统一见 [验证记录](../docs/validation.md)。旧包通过不等于新包通过。测试命令为 `python3 -B -m unittest discover -s tests -v`；虚构 `examples/walkthrough.py` 不调用模型，固定候选只检验确定性流程，不冒充真实模型提取。单元测试数量、合成 JSONL／SQLite 用例或本地待审摘要不构成真实平台接收、调度或通知交付证明。

“20 分钟临时 AI 能否从零复现同等可靠性”尚未做对照实验。比较需提前冻结同等验收标准、隔离环境、时间预算、故障矩阵和独立评审，不能以现有演示声称通过。
