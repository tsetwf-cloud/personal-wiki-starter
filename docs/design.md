# 设计说明：从实际系统中提炼什么，哪些不照搬

## 要解决的问题

用户每次临时介绍背景，容易遗漏影响建议的信息。目标不是复制人格，而是保存经本人确认、可追溯、能在新会话重新读取的上下文。

## 教学版的四层

1. 原始资料：保留说话者、时间与原文，不随结论修改。
2. 待审候选：提取有长期用途的声明，标注信息性质与落位。
3. 正式主题：只保留批准后的当前状态和必要历史，不堆聊天流水账。
4. 规则与索引：约束操作并引导按需检索，不在每次对话塞入整库。

初始化使用三类正式主题以降低入门成本。作者私人系统另有更细的基础信息、认知、生活、工作、创业分类；教学版不假装所有读者都需要同样分类，也不照搬作者的具体项目。

## 三个 Skill 为什么分开

背景读取默认只读。提取阶段允许写候选与归档，不允许写正式页。合并阶段必须有当前用户明确批准，敏感项与结构项各自审核。这能减少一次笼统更新指令承载过多含义。

这些是模型的操作规程，不是用代码强制的权限分离。Agent 仍有误操作风险；需要用户审阅、版本备份，必要时另加系统级权限控制。不要宣传安装后即可保证不误写。

## 哪些方法来自实际系统

作者实际 Wiki 采用 Markdown、索引与规范文件、受控收件箱、原文哈希、候选编号和人工审批。来源包含手动文件和明确授权的 Hermes 会话，自动化部分有本地采集、游标、锁与归档处理核心。

本次仅只读核对现有规范、索引、日志、处理核心和运行说明；没有复制个人正文或账号配置。历史配置和运行记录不作为整条链路今天仍然稳定工作的证明。公开版不包含真实账号标识。

## 哪些是本次新写的配套

空白模板、虚构练习、三份不绑定机器路径的公开 Skill、初始化与只读校验脚本，均是为本教程重新整理的入门材料。它们不包含生产系统的采集器、审批状态机或调度任务。

## 以后扩展自动化前的门槛

- 明确可读取的账号、对话与时间范围；接通机器人不代表授权采集其他聊天。
- 先保存不可改写来源，再推进增量游标。
- 重复运行无重复；异常保留来源；并发不会处理两次。
- 工具输出、内部推理和AI未采纳建议不成为用户事实。
- 自动化只提候选；敏感与第三方内容逐项批准。
- 调度、真实执行、归档结果、通知送达分别验收。

本版不提供自动化启用命令。对入门读者，手动走通一份资料比先维护四路采集器更可控。

## 能力边界

背景库只收录对任务与长期协作有用的信息，不追求全量同步。开源利于检查与迁移，但数据去向仍取决于模型、工具和辅助服务。自动采集与候选提取不能代替正式入库审批；更多背景也不能消除幻觉、偏差和过时信息。
