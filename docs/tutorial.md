# 不再每次向 AI 介绍自己：用 Hermes 搭一个可迁移的个人 Wiki

上一篇说到，我想解决的不是让 AI 模仿我的口气，而是一个反复出现的问题：聊工作、项目和生活时，总要重新介绍背景。临时想起多少就说多少，遗漏的往往还是会影响建议的信息。

我的做法是把需要长期使用的个人背景，整理成自己掌握的 Markdown 文件。AI 回答前先读取相关页面，遇到变化时先生成候选，等我确认后再更新。

这篇不继续展开概念，直接搭一个能用的入门版。你会拿到空白目录、三个 Skill、一份虚构练习资料和初始化脚本，走完建库、导入、审核、更新、换会话读取的完整过程。

**完成标准：换一个新会话，AI 能读出你已经批准的信息，同时不会把尚未批准的建议当成你的决定。**

> 配套仓库：https://github.com/tsetwf-cloud/personal-wiki-starter
> 所有示例均为虚构，不包含我的私人档案和聊天记录。本文是我的现有方法的简化教学版，不是整套生产自动化系统的复制品。

## 一、先选对起点：电脑文件夹，不是全量聊天导入

先准备一台电脑、可调用工具的 Hermes，以及一个你允许处理所选资料的模型服务。模型可能收费；本教程不承诺免费，也不包含付费开通操作。

主路线使用 Linux / macOS 终端，Windows 用户在 WSL 的 Ubuntu 终端操作。不要把后面的 Bash 命令直接粘贴到 Windows 命令提示符。Windows 已有可用 Hermes 的读者也可以按同一文件流程操作，但路径和终端命令需对应调整；本文没有在原生 Windows 或 macOS 上做整套验收。

第一次只用低敏的文字资料。不要从身份证、工资明细、家庭矛盾或整库微信记录开始。知识库是否有用，先靠一次完整操作验证，不靠导入量证明。

### 1. 没装 Hermes，先装并验证

Windows 尚未安装 WSL，可在管理员 PowerShell 执行微软提供的命令：

```powershell
wsl --install
```

按系统提示完成安装或重启，打开 Ubuntu 并创建 Linux 用户。企业受管电脑先遵守单位的软件与数据规定。WSL 安装失败先查微软说明，不要为这份教程关闭安全软件：
https://learn.microsoft.com/windows/wsl/install

在 Linux / macOS / WSL 的终端按 Hermes 官方安装指引安装：

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

这条命令会下载并执行官方脚本。想先检查脚本内容的读者，可从官方安装页查看后再运行。下载失败先排查访问与安装说明，不改用来历不明的镜像。

安装完成后重新打开终端，再执行：

```bash
hermes --version
hermes model
```

第二条命令打开提供方选择流程。选你已经获得使用资格、愿意承担费用且允许处理这些资料的服务。不要把 API 密钥贴进聊天或写到 Wiki；在 Hermes 的配置向导中完成认证。

输入 `hermes`，问一个普通问题。能收到正常回答才继续。若只会文字回答、无法读写文件，用 `hermes tools` 检查 File、Terminal、Skills 工具是否开启，调整后重新开始会话。遇到问题先运行 `hermes doctor`，不要用关闭审批来解决文件读取问题。

已有能正常工作的 Hermes，就跳过安装，不必为本教程升级或重装。

### 2. 检查练习用工具

在终端执行：

```bash
python3 --version
git --version
```

配套脚本只需要 Python 3.10 或以上，不需要 `pip install`。WSL Ubuntu 如果缺少 Python 或 Git，可以执行：

```bash
sudo apt update
sudo apt install python3 git
```

这是系统安装操作，需要管理员权限。macOS 的安装方式不同，按 Python 与 Git 官方说明安装即可，不要执行上述 apt 命令。

## 二、拿到模板，创建你自己的私人目录

终端一次执行一行：

```bash
cd ~
git clone https://github.com/tsetwf-cloud/personal-wiki-starter.git
cd personal-wiki-starter
python3 scripts/wiki_tool.py init --root "$HOME/my_personal_wiki"
python3 scripts/wiki_tool.py check --root "$HOME/my_personal_wiki"
```

如果 `git clone` 提示同名目录已经存在，先确认是不是你之前下载的这个仓库，不要删除旧目录后重来。如果初始化提示目标目录非空，换一个新的目录名，并把后面的路径一起换掉；不要强行覆盖已有资料。

成功时，程序返回 JSON，`ok` 为 `true`。报错时停止在当前步，按报错处理。脚本不会替你连接模型、采访、提取资料或安装定时任务。

你现在有两个不同目录：

- `~/personal-wiki-starter`：可公开分享的教程与模板，后面可以重新下载。
- `~/my_personal_wiki`：属于你自己的私人资料，**不要推送到这个公开仓库**。

私人目录初始结构：

```text
my_personal_wiki/
├── AGENTS.md
├── SCHEMA.md
├── index.md
├── log.md
├── 资料导入规范.md
├── 00-基础信息/
│   └── 个人概况.md
├── 01-工作与项目/
│   └── 当前项目.md
├── 02-生活/
│   └── 时间安排与兴趣.md
└── 99-收件箱/
    ├── 待导入/
    ├── 待审核/
    ├── 原始资料/
    └── 处理记录/
```

不用先记住所有文件名。`index.md` 是导航；正式主题页保存你批准的信息；收件箱处理资料；`log.md` 记录真正发生的改动。规则文件告诉 AI 怎样操作，避免每次临时发明流程。

可以用 VS Code、Obsidian 或普通文本编辑器打开私人目录。Obsidian 不是必需组件。Windows WSL 用户在终端输入 `explorer.exe .` 可以打开当前目录；想看私人目录，先 `cd ~/my_personal_wiki` 再执行。

## 三、安装三个 Skill，不把私人资料装进 Skill

Skill 是给 AI 用的操作说明。它不应该装满你的个人经历，更不等于一个能强制隔离权限的程序。

在终端执行：

```bash
hermes skills install https://raw.githubusercontent.com/tsetwf-cloud/personal-wiki-starter/main/skills/wiki-context-reader/SKILL.md
hermes skills install https://raw.githubusercontent.com/tsetwf-cloud/personal-wiki-starter/main/skills/wiki-review-intake/SKILL.md
hermes skills install https://raw.githubusercontent.com/tsetwf-cloud/personal-wiki-starter/main/skills/wiki-approved-merge/SKILL.md
hermes skills list
```

按安装器提示检查内容和确认。如果当前版本拒绝某个 Skill，先查看原因，不使用 `--force` 绕过扫描。如果提示已经安装，不要盲目覆盖自己改过的版本。

在列表中确认三个名称：

- `wiki-context-reader`：回答前按需读取背景，不改档案。
- `wiki-review-intake`：把指定资料整理成候选，不直接合并。
- `wiki-approved-merge`：只合并你明确批准的条目。

然后从私人目录开启一个新会话：

```bash
cd ~/my_personal_wiki
hermes
```

本文中，代码块里的 `cd`、`python3` 等在终端执行；下面的自然语言提示词发送给 Hermes。不要把两者粘贴到同一个输入框。

从 Wiki 根目录启动，有助于 Hermes 发现该目录的 `AGENTS.md`。如果你从手机或别的目录聊天，必须明确告诉它私人 Wiki 的实际绝对路径。仅安装 Skill 不会让所有模型和所有聊天 App 自动找到文件。

## 四、先用虚构资料练一次，确认审核真的挡住了直接写入

练习资料里有协作偏好、尚未开始的计划，以及一条没有采纳的 AI 建议。它的作用是检验 AI 能不能区分这几件事。

如果你正在 Hermes 会话里，先另开一个终端窗口，执行：

```bash
cp ~/personal-wiki-starter/examples/first_source.txt ~/my_personal_wiki/99-收件箱/待导入/first_source.txt
```

第一次使用前确认目标没有同名文件；如果练习已经做过，不要覆盖原件，先查看已有的归档和审核记录。

回到 Hermes 会话，发送：

```text
请使用 wiki-review-intake。
当前工作目录就是我的私人 Wiki 根目录。

本次仅处理 99-收件箱/待导入/first_source.txt。
这是公开的虚构练习资料，允许发送给当前已配置的模型处理。
先读取规则与索引；提取候选，保留原文、真实 SHA-256 和完整拟落位路径。
归档后核对原文哈希，候选来源改为实际归档路径。
不要修改任何正式主题页，不接入聊天记录，不创建定时任务。
最后给我审核文件路径、候选摘要和批准语法。
```

预期审核结果可参考仓库的 `examples/review_example.md`，但不要把样例当作你本次真实运行的记录：

- C01：希望 AI 先读相关背景，并独立指出问题，拟放入个人概况。
- C02：计划尝试每周整理学习笔记，尚未开始，拟放入时间安排与兴趣。
- 不进入候选：暂停项目、专做短视频。这是 AI 建议，示例用户没有采纳。

来源应进入 `99-收件箱/原始资料/2026/手动资料/`。练习资料写明资料日期为2026-10-22，所以使用这个日期，不改成你的运行日期。你以后自己的文件，应使用实际资料日期；没有可靠日期时记录接收日期并注明。

### 你要亲手检查的内容

打开 AI 返回的审核文件，确认每条都有原文、类型、建议写法和完整落位路径。再打开三个正式主题页，确认它们仍然没有练习内容。

**如果正式页已经出现候选内容，先停在这里。** 这是越过审核边界，不是成功。让 AI 对照修改前的备份撤回越权修改，并核对原文与候选；没有可靠备份时不要让它凭记忆覆盖旧页。等规则与行为核对后再继续。

归档成功但没有正式入库是正常状态。归档回答原文放在哪里，审核回答是否应该成为长期背景，两者不是同一个动作。

## 五、只批准一项，看看未批准的信息会不会偷偷混进去

在同一会话发送：

```text
请使用 wiki-approved-merge。
批准 first_source 的 C01；C02 保持待审核，不批准其它内容。
合并前保留受影响页面的本地可恢复版本，不要推送到远端。
只写入候选已声明的位置，更新来源、日期和日志。
完成后报告已合并、拒绝、仍待审核的编号。
```

如果实际候选编号不同，先打开审核文件核对，再把指令里的编号改为真实编号，不要照抄一个不存在的 C01。

检查四个结果：

1. `00-基础信息/个人概况.md` 出现批准的协作偏好，并带来源。
2. C02 仍是待审核，正式生活页没有把每周整理笔记写成既有习惯。
3. `log.md` 记录本次批准、候选编号和目标页。
4. 原始资料没有改写；同一来源归档前后的 SHA-256 一致。

你也可以明确拒绝 C02。拒绝应记录为拒绝，不删除来源，也不反复把同一条重新推荐给你。只要仍有待审项，整份审核记录就留在待审核区；全部批准或拒绝后再归入处理记录。

模板中的 YAML 只是页头元数据。AI 合并时应把 `updated` 改为真实修改日期，填写真实来源；不要为了让文件看起来完整而补不存在的经历。

## 六、换一个新会话，验证 AI 是否真的读取了 Wiki

退出当前会话，再从同一个私人目录启动 `hermes`。新会话里发送：

```text
请使用 wiki-context-reader。
当前目录是我的私人 Wiki。先读取索引和相关正式主题页。
告诉我：我希望你怎样给我建议？
再告诉我：我是否已经开始每周整理学习笔记？
列出你实际读过的文件；只用正式页作答，不读待审核或原始资料。
不知道的内容请说不知道，不要靠之前聊天的记忆补齐。
```

合格结果应读出 C01 的协作偏好。对第二个问题，正式页还没有记录已批准的事实，AI 应说明正式资料不足以确认，不能回答你已经形成了这个习惯。

这比问一句你记不记得我更有用。AI 可能通过聊天记忆碰巧答对，却没有读取文件。要求给出实际读取路径，才能检查这次使用的是哪一份上下文。

如果回答只有泛泛建议，没有文件读取，重新指定 Wiki 路径和 Skill，并检查文件工具。不要用继续闲聊来掩盖检索没有生效的问题。

## 七、练习通过后，再放你自己的低敏资料

不必第一天写完整个人传记。先给会影响眼前任务的信息：当前在做什么、目标是什么、有哪些时间和资源限制、希望 AI 怎样协作。

可以把下面这段发给 Hermes：

```text
我想建立自己的个人 Wiki，先做一次低敏访谈。
每次最多问两个问题，只问会影响当前项目或日常协作的信息，不追求填满档案。
先问当前项目与实际时间约束，再问协作偏好；允许我跳过。
不要索要真实姓名、身份证、精确住址、账号凭据、收入或家庭成员隐私。

我说访谈结束后，只将这次访谈中我本人提供的信息写成待导入来源。
写入前让我确认这份材料可以由当前模型继续整理。
然后生成候选，等我逐项审核，不直接合并。
AI自己的建议不能当成我的决定。
```

你也可以自己写一页 `.md` 或 `.txt` 放入待导入目录，按第四步处理。一个文件围绕一个主题，先从少量内容开始。

以后有变化，不要让 AI 直接把旧资料全文替换掉。例如你说这两个月周末没有固定学习时间，需要留下时间与适用范围，不能把长期安排永久改成没有空闲。信息冲突先区分时间变化、口径不同和真正矛盾。

## 八、日常只需要两个动作：带背景提问，定期清候选

### 带背景提问

以后可以这样问：

```text
先使用 wiki-context-reader 读取我的当前项目和时间安排。
结合已经批准的限制，帮我安排本周任务。
先列本次实际读过的页面；缺少会改变安排的关键信息，再向我询问。
这次只给建议，不写入Wiki，也不创建或发送日程。
```

你不必重讲所有背景，但仍需说明当前任务。个人 Wiki 不能替你定义这次想完成什么。

### 定期处理候选

起步阶段建议手动触发，每次只处理一个来源。审核时关注内容对不对、类型对不对、落位对不对。不要养成不看内容就批准全部的习惯。

我自己的系统在手动文件以外，还接入了获授权的 Hermes 终端对话和指定微信、Telegram 私聊，采用增量归档、候选审核与统一通知。但它不等于读取所有微信联系人，也没有接入 ChatGPT 官网或 App 的全部历史。

自动采集要额外处理精确会话白名单、消息标识、游标、去重、并发锁和失败恢复。本仓库**没有附送这些采集器，也没有自动开启每天更新**。先把手动闭环做对，之后再单独实现自动化，比复制一组定时任务后不知道它读了谁、写了什么更稳妥。

若要继续做自动化，至少先验证：只读指定对话；重复运行没有新增；来源写成功才推进游标；失败不丢原文；候选不直接合并；通知目的地准确。配置已保存、脚本测试通过、调度器真实执行、消息实际收到，是四个不同的验收结果。

## 九、备份、迁移和隐私，别留到最后

### 私人文件不跟公开教程一起发布

公开仓库只放模板、虚构示例和方法。你的私人 Wiki 放在仓库之外。`.gitignore` 只是减少误提交，不是阻止泄漏的权限系统，更不会替你判断一段文字是否属于隐私。

第一次运行真实资料前，给私人目录做一份备份。可以用你信任的本地备份软件。需要通过云盘或私有 Git 远端备份时，先判断你是否允许相应服务保存这些内容；私有仓库不等于端到端加密。

迁移到另一台机器时，复制整个私人目录，包括规则、来源和日志，再安装 Agent 并指定新路径。不要只搬正式页，否则会丢掉来源与审核历史。用新会话按第六步复测，不把文件已复制等同于 Agent 已经读取。

### 开源、本地文件、离线推理不是同一回事

Hermes 开源、Wiki 存在自己电脑里，解决的是可检查性和可迁移性的一部分问题。如果你调用云端模型，读取的正文仍可能发给模型提供方；压缩、语音识别等辅助功能也要分别检查数据去向。

不愿上传的资料，不要先发进云模型，再加一句仅限本地。标记不能撤回已经发送的内容。真正的本地处理需要本地模型和经过验证的工具、网络边界，本教程不提供这一保证。

健康、投资和职业等高影响决策，背景充分只能减少部分信息缺失，不能证明建议正确。数字分身只是个人上下文的一个有缺漏、会过时的工作副本，不是完整的你，也不是替你拍板的权威。

## 十、排错时，先看卡在哪一步

- 提示 `python3: command not found`：先完成 Python 安装，不需要安装一堆 AI 库。
- 提示目标目录非空：初始化保护生效。换新路径，别覆盖真实 Wiki。
- Skill 安装失败：确认 raw.githubusercontent.com 可访问、Hermes 支持直接 URL 安装，查看官方说明；也可让 Agent 阅读仓库中的 Skill 文件，但不能声称已经完成全局安装。
- 换会话后不知道 Wiki 在哪里：从私人根目录启动，或明确提供实际绝对路径。
- 只生成候选，没有更新正式页：这是默认流程，审核后再明确批准。
- AI 越过审核直接修改：暂停后续合并，对照备份修复，不能把这次当作验收通过。
- `check` 成功但建议仍然不对：脚本只检查结构与支持范围内的链接，不验证信息真伪、隐私完整性和模型判断。检查正式页是否准确，再检查本次是否读到了相关页。

## 最后一次验收

别只看文件夹建出来没有。自己走一遍：

- 新目录初始化成功，重复初始化不会覆盖原资料。
- 虚构资料生成候选，正式页保持不变。
- 批准 C01 后只有 C01 入库，C02 仍待审。
- 换会话后能读到批准的信息，不把计划或AI建议说成既成事实。
- 原始来源保留，哈希可核对，日志能解释一次修改。
- 私人资料没有混入公开仓库，清楚哪些正文可能发送给云端模型。

这些成立，再逐步增加真实资料。先让它准确记住一件你批准的事，比让它一次记下所有事情更有用。
